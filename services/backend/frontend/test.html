Bring your own video, photo or city dataset — this page runs the same pipeline the dashboard uses.
Video Input POST /jobs/video
How this works. Pick a bundled clip (nothing is uploaded — the server reads it from disk) or upload your own. Frames are detected, plates are OCR'd, reads are voted across consecutive frames per track, then logged.
Sent as source_path, so the 184 MB clip never crosses the wire.
Any format OpenCV can decode (mp4 / mov / avi / mkv).
Pipeline parameters
A plate must be read this many times across consecutive frames before it is logged. This is the cross-frame voting that makes video far more accurate than a single still.
max_frames defaults to 300 so a demo run finishes in about 15 seconds instead of chewing through a whole clip. On the bundled ANPR clip the first plate is only readable around frame 130, so a much smaller cap will legitimately find nothing — raise the cap rather than concluding the detector is broken. ocr_every=3 means detection runs on every frame but OCR only on every 3rd — that is where most of the compute saving comes from.
Region code used to validate plate format. IN = India.
Honest caveat on single stills. A photo gives you the model's raw OCR accuracy. In video the pipeline sees the same plate across consecutive frames and votes across those reads, which repairs most single-frame character errors. One still has nothing to vote across, so expect noticeably lower accuracy than the video numbers — this is a documented property of the underlying ALPR model, not a bug in this page.
jpg / png / webp. A reasonably legible plate helps.
Sent as source_path — useful for files already on the host.
