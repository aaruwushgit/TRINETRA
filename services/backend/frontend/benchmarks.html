Central — pros / cons

                
    
                
      
              
      
              
      
                
      Edge — pros / cons
      
                
        
                
          
              
          
            
          
          
          
          
          
            
          
              Why placement dominates the bill.
          
              A 1080p H.264 traffic stream is a few Mbps, continuously, whether or not a vehicle passes. A
              structured plate event — camera, timestamp, plate, confidence, vehicle type, speed — is a few
              hundred bytes, and only exists when a vehicle actually passes. Shipping video to a
              datacentre means buying city-wide uplink capacity sized for the worst case, 24/7. Shipping
              events means the network cost tracks real traffic and collapses by three to four orders
              of magnitude.

          
              Central also pays for decode. Every analysed frame has to be
              decoded before inference. At the edge the decode happens once, next to the sensor, on hardware
              you already bought. Centrally it is a per-camera per-frame cost on the expensive tier — and it
              is measured, in the per-stage panel above.

          
              The honest caveat. The bandwidth arithmetic is arithmetic over an
              assumed per-camera bitrate. Any accelerator count assumes a GPU class this laptop is not, and
              was never benchmarked against. Only the per-frame, per-crop, per-event and decode costs above
              were actually timed here.

          How the measured numbers were takenmeasured
          
            
            
              
          • Warmup discarded. The first detection frames and OCR reads are thrown away —
                they include model load, lazy kernel compilation and cache warming.
            • 
              
          • p50 and p95, not means. A single stalled frame skews an average; p95 is what
                a latency budget has to survive.
            • 
              
          • Resolution is stated, because detection cost is governed by the letterboxed
                inference size, not the source frame size. A figure quoted without it is not a figure.
            • 
              
          • Single stream, single process. No contention from neighbouring workers,
                which a real host will have.
            • 
              
          • Database suites run against a throwaway database created for the run and
                deleted afterwards, with synthetic seeded rows — never the live one.
            • 
            
          
          
          
          
          
            
          What the projections assumeassumption
          
            
            
              
          • Linear extrapolation. Fleet cost = measured single-stream cost × streams.
                Real systems benefit sub-linearly from batching and suffer super-linearly from contention;
                neither is modelled.
            • 
              
          • Accelerator class is an assumption. Any GPU count is the measured per-frame
                cost divided by an assumed speedup for an assumed device. Nothing of that sort was
                benchmarked here — treat GPU counts as order-of-magnitude sizing, not a purchase order.
            • 
              
          • Uniform traffic. Events per second is an average; peak hour on an arterial
                road runs several times the mean, which is what the headroom slider is for.
            • 
              
          • Storage is structured events only — rows and indices, not retained video or
                plate crops, which dominate every other storage line by orders of magnitude.
            • 
              
          • Real deployments add overhead not modelled here: stream reconnects, model
                rollout, replication, monitoring, egress. Budget above these numbers, never at them.
            • 
              
          • No prices. This page deliberately quotes no currency figures, because no
                hardware or bandwidth pricing was measured or sourced.
